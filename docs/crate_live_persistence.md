# Bounded live crate approach

The user requested a live test after the stationary comparison. This separate
default-OFF experiment connects verified image groups to the existing guarded
physical-property memory. Main, primary comparison, PR117 and previous demos
remain unchanged. All original association and failed-view results are retained.

`--image-object-property-persistence` maintains a separate transactional memory
inside the image-group state. It uses the existing persistence configuration,
original source clocks, confidence decay, expiry, competitor and support-change
checks. Acquisition follows the existing explicit freeze operation. Group
membership does not transfer raw track identity. Only exact currently accepted
points receive the group policy; a failed/absent group loses its property memory.
Raw geometry remains in the original occupancy/unknown-policy pipeline.

Mass/contact can persist; kinetic and route interaction stay current. This is
not partial-surface recovery: every group still needs the original full support,
mask IoU, repeated-source and ambiguity gates. A changed view may therefore lose
the grouped assessment even though ordinary obstacle navigation can continue.
The current image-space mask comparison is itself a bounded-view limitation.

`--image-object-approach` is limited to the original 640-pixel demo-container
view, no humans or changed standoff, local contact and overlap hold enabled,
unchanged deskew and sixty stationary fields. It authors a straight 0.40 m
nominal segment, with the original final-goal tolerance (so actual travel is
shorter), actuator limits, fixed lambda, MPC, CBF, independent clearance and
stopping checks. This is a measurement approach, not a pass-by demo. The longer
segment allows the unchanged minimum of ten translating field updates to be
tested. No route knowledge enters the estimator.

`configs/restaurant_crate_live_approach.json` uses the original licensed broken
crate scene. The existing frozen-source launcher requires a matching independent
stationary gate before motion. The motion run repeats its own sixty-field gate
and requires a current group containing mass/contact sources before wheels.
Motion acceptance and continued grouped-property acceptance must be reported
separately; arrival alone is not a perception pass.

Pre-native validation: 3,778 unit tests pass in 187.99 s, 46 focused tests pass
in 55.01 s, and the expanded ten persistence/CLI tests pass in 36.95 s. Ruff
across robot/scripts/tests, compilation and diff checks pass. The six new CLI
cases were added after full-suite collection and are covered by the ten-test run.

Native validation is pending. Artifacts belong under
`outputs/crate-live-persistence/`; preserve every failure. No calibrated mass,
physical sharpness, complete four-factor sensing or real-time claim is made.
